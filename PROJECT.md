# Build LifeOS — A Personal Life Dashboard

## Role & Behavior
You are a senior UI designer and front-end developer with the taste of someone who designs at Linear, Whoop, or Apple. Every decision should be restrained, intentional, and technically rigorous. Default to minimal. Never decorative. When in doubt, do less. Treat every screen like it could ship to the App Store tomorrow.

## Inspiration & Visual Reference
Before writing a single line of code, internalize the visual language of these sites:
- **linear.app** — the gold standard for minimal premium dark UI, typography, density, and spacing
- **whoop.com** — dark mode done right, big numbers, ring visualizations, serious athlete energy
- **stripe.com** — homepage hero is the reference for subtle gradient atmosphere done tastefully
- **railway.app** — clean dark SaaS aesthetic, strong typography hierarchy
- **vercel.com** — premium spacing and typographic restraint

The site should feel like it belongs in this company. Someone should look at it and think it was built by a small elite design team, not generated by AI.

- **Tailwind CSS** for all styling — strict 4/8/12/16/24/32/48/64px spacing scale only, no arbitrary values
- **shadcn/ui** for all component primitives — Button, Input, Dialog, Select, Tabs, Card, Tooltip, Toast, DropdownMenu, Badge. Install it first, use it for everything interactive.

## Design System — Build This Before Anything Else

Before building any screens, build the design system. Every screen uses it. Nothing gets hardcoded.

### Colors

```css
--background: #0A0A0A
--surface: #111111
--surface-raised: #161616
--border: rgba(255,255,255,0.05)
--border-hover: rgba(255,255,255,0.10)
--text-primary: #FAFAFA
--text-secondary: #A0A0A0
--text-tertiary: #666666
--accent: #00FF88
--accent-dim: rgba(0,255,136,0.15)
--accent-border: rgba(0,255,136,0.25)
--danger: #FF4444
--warning: #FFB800
```

The accent color is the most important color in the app precisely because most things are NOT it. Every use of `#00FF88` should feel earned. Make it swappable via one token — users unlock alternate accent colors through leveling up.

### Background Atmosphere
Add a subtle radial gradient mesh layer BEHIND everything — fixed position, pointer-events none, z-index 0:
- 3 blurred color blobs: one accent green, one deep blue (#1a1a4e), one deep purple (#2d1b4e)
- Each blob: 600-800px diameter, blur 120px, opacity 12-18%
- Positioned off-center (top-right, bottom-left, center-right)
- Should be felt, not seen. If someone notices it immediately, it's too strong.
- NOT bright. NOT purple-to-pink AI gradient. Almost imperceptible.

### Typography
Use `next/font/google`:
- **Display/headings:** `Instrument_Sans` or `Inter_Tight` — weight 500, 600 only. Never 700+.
- **Body:** `Inter` — weight 400, 500
- **Mono (numbers, timers, weights):** `JetBrains_Mono` — weight 400, 500

Set as CSS variables: `--font-display`, `--font-body`, `--font-mono`

Rules:
- Body: 15px, line-height 1.6
- Headings: letter-spacing -0.02em
- Big numbers: `--font-mono`, weight 500, 36-48px based on context
- Sentence case everywhere. Never Title Case. Never ALL CAPS.
- Max two weights on any screen: 400 and 500. Occasionally 600 for primary heading only.

### Motion Rules (Framer Motion)
- **Viewport entry:** opacity 0→1, y 12→0, duration 0.4s, ease "easeOut", once: true, margin "-80px"
- **Button hover:** scale 1.02, duration 0.2s
- **Card hover:** y -2px, border brightens, duration 0.2s
- **Tab transitions:** cross-fade 0.2s
- **Number updates:** count up via custom `useCountUp` hook, 600ms
- **Ring fills:** 800ms ease-out on mount, 400ms on update
- **Page mount:** stagger children by 0.05s
- Nothing bouncy. `type: "tween"` everywhere. Nothing slower than 600ms or faster than 150ms.
- Respect `prefers-reduced-motion`.

### Core Reusable Components (build all before any screens)

**Ring** — animated SVG progress ring
- Props: value (0-100), size, strokeWidth, color, label, sublabel
- Fills smoothly on mount (0 → value, 800ms ease-out)
- Updates animate smoothly

**StatCard** — dark surface card with number, label, optional trend
- Hover: translateY(-2px), border brightens
- Number counts up on mount via `useCountUp`
- Optional sparkline

**XPBar** — horizontal progress bar, accent green fill
- Shows level, XP value, XP to next level
- Lives in header

**StreakBadge** — lucide `Flame` icon + streak count
- Accent green when active, gray when broken

**ChatMessage** — coach chat bubble
- User: right-aligned, accent-dim background
- Coach: left-aligned, surface background, typing indicator (3 pulsing dots)
- Timestamp in text-tertiary

**NumberInput** — large touch-friendly input for workout logging
- 64px minimum tap target
- Minus/plus buttons either side
- Center number in JetBrains Mono at 24px
- Designed for sweaty thumbs mid-workout

**EmptyState** — for every section with no data
- Centered lucide icon at 40px in text-tertiary
- One-line description in text-secondary
- Primary action button

**SkeletonLoader** — shimmer loading state
- Dark base, slightly lighter shimmer animating across
- Used instead of spinners everywhere

## Gamification System

Premium and earned, not childish. Build early, thread through everything.

**XP sources:**
- Complete a workout: +50 XP
- Hit a PR: +100 XP
- Complete a task: +5 XP
- Submit assignment on time: +25 XP
- 7-day streak: +200 XP bonus
- Weekly coach check-in: +30 XP

**Levels:** 1-100, scaling XP requirements. Each level unlocks a cosmetic reward (alternate accent color, alternate ring style, alternate theme). Show level + XP bar in header.

**Streaks:** workout streak, task-completion streak, weekly consistency streak. Motivate, don't guilt. No dark patterns.

**Achievements:** monochrome milestone badges. First workout, 10 workouts, first PR, 7-day streak, first syllabus uploaded, 30-day streak. Minimal — icon + label, subtle unlock animation.

**Daily rings:** Three rings on Today. Close by logging workout, completing tasks, keeping assignments on track.

**PR celebrations:** New number counts up with brief light sweep. `navigator.vibrate([100, 50, 100])`. No sound by default.

**No guilt-trip notifications. One gentle daily reminder max.**

## Section 2: Coach

The most important screen. Polish this the most.

**Layout:**
- Full-height chat interface
- Header: "Coach" in display font, "powered by Claude" in tiny text-tertiary
- Message list: scrollable, newest at bottom, auto-scrolls on new message
- Input bar: fixed at bottom, text input + send button, placeholder "Ask anything..."

**Messages:**
- User: right-aligned, accent-dim background, accent-border border
- Coach: left-aligned, surface background, border, typing indicator while thinking
- Timestamps in text-tertiary below each message

**Coach personality:** Direct, warm, no-nonsense. Like a knowledgeable older brother who lifts. Calls me David. No corporate AI-speak. No exclamation points. Concise. Pushes back when I'm wrong. Has opinions.

**Mock response engine (keyword matching for v1):**
- "deload" / "recovery" → training recovery advice referencing recent workout data
- "bench" / "squat" / "deadlift" / "lift" → references recent logged sets and progression
- "calories" / "macros" / "eat" / "nutrition" → practical nutrition advice with specific numbers
- "tired" / "exhausted" / "sleep" → sleep and recovery advice
- "study" / "exam" / "assignment" / "school" → study scheduling advice
- "motivation" / "stuck" → direct motivational response, no fluff
- "creatine" / "protein" / "supplement" → evidence-based supplement advice
- "PR" / "personal record" → celebrates it, suggests next target
- "cardio" / "run" / "conditioning" → cardio programming advice
- "cut" / "bulk" / "recomp" → body composition strategy advice
- "split" / "program" / "routine" → training program recommendations
- "injury" / "pain" / "hurt" → does NOT prescribe, expresses care, recommends seeing a professional
- "sad" / "depressed" / "anxious" / "struggling" → expresses genuine care, does NOT try to coach through it, points to LMU CAPS (310-338-2868) and the 988 Lifeline
- Default fallback: in-character generic response referencing David's profile and recent activity

**Context chips above input:** scrollable row of small chips showing what coach knows — "12 workouts logged", "3 classes", "Last weight: —". Tap a chip to ask coach about it.

**Onboarding prompt:** if profile not set up, show a gentle "Complete your profile so I can actually help you" message as the first coach message with a Setup Profile button.

**Personality presets (in Settings):** Direct / Warm / Drill Sergeant / Older Brother

**API route ready:** build `/api/coach` in Next.js as a stub ready to wire up to Anthropic API later. For v1, all responses are mock. When the real API is connected, the mock engine is replaced with the actual Claude response.

**Guardrails baked into the future system prompt:**
- Not a doctor, therapist, lawyer, or licensed nutritionist
- Never advises extreme cuts, dangerous training, or anything harmful
- Mental health topics: express care only, point to real resources, never coach through it
- Injury topics: express concern, recommend professional, never prescribe

**Chat history:** persist to localStorage for v1, migrate to Supabase once auth is set up.

## Section 3: Workouts

Two sub-tabs: **Log** and **Progress**

### Log Sub-tab

**Routines:**
- Saved templates: exercises, order, target sets/reps, rest timer defaults per exercise
- Drag to reorder exercises
- Pre-built starters: Push, Pull, Legs, Upper, Lower, Full Body
- Routine folders by training block ("PPL Block 1", "Cutting Phase")
- "Start empty workout" for freestyle sessions
- "Start from routine" pre-fills with last session's weights

**Exercise Library:**
- Pre-loaded with common lifts: barbell, dumbbell, cable, machine, bodyweight, cardio
- Each tagged: body part, equipment, primary muscle
- Custom exercises with same tags
- Search by name, body part, equipment
- Recent exercises surface first

**Active Workout Screen (the most important UX in the app):**
- One screen, exercises stacked vertically
- Each exercise card:
  - Exercise name + body part tag
  - Set rows: set number, **PREVIOUS column** (last session's reps × weight — always visible, right next to today's input), today's reps input, today's weight input, completion checkbox
  - The Previous column is the single most important UX feature. Never hide it.
- Tapping checkbox: marks complete, auto-fills target if blank, **auto-starts rest timer**
- NumberInput components for reps and weight — big, thumb-friendly
- Add set button below each exercise
- Swipe left on a set to delete it
- **Plate calculator:** tap any weight field to see a plate breakdown (configurable bar weight: 45/35/15 lb)
- **Warm-up calculator:** for any working weight, generate suggested warm-up progression
- **RPE input:** optional, hideable, 6-10 scale per set
- **Set notes:** per set, optional ("felt heavy", "form broke")
- **Set types:** warm-up (excluded from PRs), working, drop set, failure, AMRAP
- **Supersets:** group exercises as A1/A2
- **Failed set tracking:** fewer reps than planned = marked missed, still saved
- Add exercise mid-workout
- Reorder exercises mid-workout
- "End Workout" requires confirmation, shows summary before saving
- "Discard" requires stronger confirmation
- Resume in-progress workout if tab is closed

**Rest Timer:**
- Auto-starts on set completion
- Big visible countdown (JetBrains Mono, 48px) with exercise name and next planned set
- Configurable: per-workout default, per-exercise override, per-set override
- +15s / -15s quick adjust
- Skip Rest button
- Screen wake lock so phone doesn't sleep
- Vibration pulse at zero
- Visible on workout screen — don't rely only on browser notifications (iOS Safari background unreliable)
- Optional sound (off by default)

**During Workout Header:**
- Workout duration timer (mono font)
- Total volume updating live (sets × reps × weight, counts up animation)
- Number of PRs hit this session

**Workout Summary (shown before saving):**
- Total time
- Total volume
- PRs hit (with animation for each)
- Body parts trained
- Estimated calories
- Option to add workout note

### Progress Sub-tab

A real analytics dashboard. This is what makes the Coach useful.

**Overview cards (StatCard components):**
- Current workout streak + longest ever
- Workouts this week / month vs. target
- Body weight trend sparkline (last 30 days)
- Recent PRs (last 30 days) with date
- Weekly volume (last 8 weeks) as bar chart

**Per-exercise progression:**
- Searchable exercise dropdown
- Four chart views: top set weight, estimated 1RM, total volume, working set reps at given weight
- Date range: 30d / 90d / 6mo / 1yr / all time
- Tap data point to see the source workout
- PR markers as small dots on the chart line

**Estimated 1RM:**
- Epley formula: weight × (1 + reps/30)
- Shown on every working set during logging
- Tracked over time as a progression metric

**PR Leaderboard:**
- All-time PRs: bench, squat, deadlift, OHP, row, pull-up + any custom exercise flagged "track PRs"
- Each shows: weight × reps, date, estimated 1RM
- Tap to see full workout context

**Body part frequency heatmap:**
- Calendar grid, last 90 days
- Color intensity = training volume
- Catches imbalances ("no hamstring work in 3 weeks")

**Weekly volume per body part:**
- Stacked bar chart, one bar per week
- Optional research-backed ideal volume ranges toggle

**Body measurements:**
- Log: body weight, body fat %, chest, arms, waist, thighs
- Charts per measurement over time
- 7-day average smoothing toggle
- Goal weight marker with ETA based on current trend
- Optional progress photos (stored in Supabase Storage, never sent anywhere without explicit per-action confirmation)

**Workout consistency calendar:**
- GitHub contribution graph style
- Full last year
- Tap any day to see workout

**Smart insights (rule-based, no AI):**
- "You haven't trained chest in 7 days"
- "Bench hasn't progressed in 4 weeks — consider varying rep ranges"
- "Weekly volume down 30% from last month"
- "12-day workout streak — longest in 3 months"
- These also surface in Coach chat with deeper analysis

**Export:**
- All data as CSV
- Single workout as clean text summary
- "Share PR" generates a minimal shareable card

## Polish Rules (apply everywhere, always)

- **Every interactive element has a hover state.** Every one.
- **Every form input has a focus ring:** `ring-1 ring-accent/40`. Never default browser blue.
- **Every section with possible empty data has an EmptyState component.** No blank sections.
- **Every loading state uses SkeletonLoader, not a spinner.**
- **Numbers over 999 use `Intl.NumberFormat` for comma formatting.**
- **Dates use `toLocaleDateString` with explicit options. Never raw timestamps.**
- **Disabled states:** opacity-40, cursor-not-allowed, no hover effects.
- **Mobile tap targets:** minimum 44px, preferably 48px.
- **No position: fixed inside scrollable containers.**
- **Images have explicit width/height to prevent layout shift.**
- **All async operations have loading, success, and error states.**
